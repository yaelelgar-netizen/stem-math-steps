Generated by `_ref/_tools/build_lomda.py`. Do not hand-edit `index.html` or

    cd _ref/_tools

    python build_lomda.py      # content.json -> this folder

## What is here and what is not

Texts and interactions are complete: all 30 screens, every approved string, all 11
answer keys, the two popups, the step-ruler applet, scoring and the QA bridge.

**Artwork is not.** Every image is an `.art` slot that renders a labelled
placeholder. When approved assets arrive, drop them in and re-run:

    assets/diagrams/    the question diagrams (Q1A.png, Q5.png, …)
    assets/screens/     per-screen backgrounds

A slot whose file exists becomes a `background-image`; one whose file is missing
stays a placeholder. Same box either way, so nothing reflows on delivery.
`--with-art` copies the current reference renders in for a preview.

## Checking it

Open `index_dev.html` — double-clicking it from the filesystem is fine. The header
must read **30 (1…30) ✔ הגשר עובד**, and the arrows step through every screen. That
proves the page exposes its screens the way the QA harness expects, independently
of any repo or deployment question.

`index.html#7` also opens screen 7 directly, which is quicker for reviewing one
screen.

Two things that had to be right for this to work, and are easy to break again:

- **The previewer talks over `postMessage` only.** Reading
  `iframe.contentWindow.TOTAL_SCREENS` works over http but throws on `file://`,
  where Chrome gives every file its own opaque origin. That left every control
  dead and the iframe stuck on screen 1.
- **`script.js` scales the stage** (`fitStage`). The design is a fixed 1920×1080
  canvas; without a scale transform it overflows at any smaller size, `overflow:
  hidden` clips the rest, and the navigation ends up off-screen — which looks
  exactly like "only the first screen works". Centring uses explicit negative
  margins, because grid `place-items: center` does not reliably centre an item
  larger than its container.

## The QA contract

לומדת כימיה 1 was finished and correct yet reported "0 pages". These details are
what that cost, so they are not stylistic:

- `styles.css` and `script.js` at the **root**, not under `css/` and `js/`
- `goTo`, `TOTAL_SCREENS` and `lomdaState` are **top-level globals**, no IIFE
- screens are **1-based**: `<section class="screen" data-screen="1..30">`
- `<div id="app">` wraps them
- posts `LOMDA_SCREEN_CHANGED` and `LOMDA_COMPLETE` to `window.parent`
- no SCORM manifest; `.nojekyll` present

## Scoring

Eight questions, equal weight (12.5 marks each). שאלה 1 splits three ways across
א/ב/ג and שאלה 2 two ways, so a sub-part carries a fraction of one question's
marks. 70 and above reports **בוצע בהצלחה**.

Two decisions the script does not specify, flagged rather than hidden:

- **Multi-select is all-or-nothing** — the exact set must match. No partial credit.
- **Marks are awarded on the first check only.** The learner can revisit a screen
  and change their answer to see the feedback again, but the recorded mark is
  frozen, so revisiting cannot farm score.

## Layout

The design is a fixed 1920×1080 stage; every coordinate in `styles.css` is a real
PSD coordinate, and the stage scales to the viewport. RTL throughout — and in this
design **forward is on the left, back on the right**.
